01 — Get started

Run Sosopo with Docker Compose

Sosopo has a web service and a worker. Keep both running: the worker delivers scheduled posts and records results.

cp .env.example .env
# Set SOSOPO_ENCRYPTION_KEY in .env first
docker compose up -d --build
docker compose ps
  1. Open the workspace and create the one-time administrator account.
  2. Set a public HTTPS URL before configuring OAuth or SSO.
  3. Use PostgreSQL for production or multiple workers; SQLite suits a small single-instance deployment.
Protect the encryption key.SOSOPO_ENCRYPTION_KEY encrypts stored channel and AI credentials. Keep it private and persistent; changing it makes existing encrypted credentials unreadable.

02 — Channels

Connect destinations, not just platforms

Each channel can have multiple destinations. Connect several Facebook Pages, Telegram channels, or LinkedIn authors, then select exactly where every post goes.

OAuth connection

Use Connect in Channels for Facebook, Instagram, Threads, X, and LinkedIn when OAuth is configured. Approve the account and select a returned Page, profile, or author.

Manual connection

Use Connect to enter a Telegram bot token and chat ID, Discord incoming webhook, or an approved provider access token.

Provider requirements

ChannelWhat you need
Facebook / InstagramA Meta app, approved permissions, and a Page manager. Instagram must be a linked professional account.
Threads / X / LinkedInProvider OAuth credentials and the relevant publishing scope.
TelegramA BotFather token and a channel/chat where the bot can post.
DiscordAn incoming webhook URL for the target channel.

03 — Publishing

Create one post for several channels

  1. Select every platform that should receive the post.
  2. Select at least one connected destination for every selected platform.
  3. Write post copy, attach images, and choose a timezone-aware time—or leave it blank for a draft.
  4. Save. Review history, retry a failed delivery, remove queued content, or delete published content from supported channels.

Attach up to 10 PNG, JPEG, GIF, or WebP images (maximum 5 MB each). Provider limits are validated before save; X accepts up to four images and Instagram requires an image.

Timezone behaviorChoose a local date, time, and IANA timezone such as Asia/Hong_Kong. Sosopo stores the result in UTC for reliable delivery.

04 — AI writing

Configure AI per workspace or instance-wide

Workspace admins can save their own provider key in the AI providers tab; it overrides the instance-wide configuration for that workspace only. Instance administrators manage the instance-wide fallback with the scope selector. Collaborators use the composer’s AI writer without ever seeing credentials.

  1. Set SOSOPO_ENCRYPTION_KEY and restart Sosopo.
  2. In AI providers, choose the scope and provider, paste the API key, select a default model, and save.
  3. Click Refresh model list after saving the key to retrieve the account-visible models.
  4. Use Remove API key to delete the saved encrypted key and cached model list for that scope.

Presets include OpenAI, Claude, Gemini, OpenRouter, Grok, DeepSeek, Kimi, MiniMax, and Z.AI GLM. Claude uses Anthropic's native Messages API; the rest use OpenAI-compatible endpoints. OpenRouter can list models without a key; other providers usually need the saved key.

05 — Media studio

Generate media, review it, then publish

Editors open the Media tab, choose image or video, an aspect ratio, a provider, and describe the result — optionally with a brand-style hint. Jobs run in the background with live status and progress.

  1. Queue a generation; one AI-media credit is charged and automatically refunded if the job fails.
  2. A workspace admin reviews the finished result and approves or rejects it.
  3. Approved images join the workspace library and can be attached in the composer with one click.
Moderation is mandatory.Pending or rejected media can never be attached to a post, and generated assets are only usable inside the workspace that created them.

Image generation works with OpenAI-compatible image APIs; video uses the OpenAI-style asynchronous video flow. Providers without a supported media model fail with a clear message rather than guessing.

06 — Workspaces

Share workspaces with the right roles

Posts, media, and channel connections belong to a workspace. Everyone starts with a personal workspace, can create more with New workspace, and switches between them with the selector in the top bar. Everything you see and do is scoped to the active workspace, on the server.

Workspace roleAllows
ViewerRead the queue, channels, and delivery history.
EditorCreate, schedule, publish, retry, and remove posts; upload images; draft with AI.
AdminAlso connect, rotate, and disable channel accounts and manage members.
OwnerAlso grant or revoke the admin role. The creator owns the workspace and cannot be removed.

Workspace admins add existing accounts by username or send expiring email invitations with a role from Team → Workspace members; if email is not configured, Sosopo shows the invite link to share manually, and recipients accept at /invite. Instance administrators create local accounts in Team → Instance accounts; optional OpenID Connect supports Google Workspace, Microsoft Entra ID, or a compatible Active Directory federation issuer, and hosted deployments can enable self-service signup. Upgrading an existing installation is safe: every existing user automatically receives an isolated personal workspace holding exactly the data they already owned.

The Workspace overview shows plan, usage against limits, channel health, and media jobs. Admins can export the workspace as secret-free JSON; the owner can set a monthly AI budget cap, upgrade the plan on hosted deployments, or delete the workspace.

Each user can set default timezone, reusable signature, and password in Settings. Changing a password signs out other sessions.

07 — Operations

Keep the workspace dependable

Self-hosted or hosted

Self-hosted (the default) keeps every workspace unlimited and signup closed. Setting SOSOPO_DEPLOYMENT_MODE=hosted starts new workspaces on the free plan, meters usage, enables self-service signup, and activates Stripe billing when keys are configured. Complete provider app review (Meta, X, LinkedIn) before opening a hosted service to the public.

Incident quick checks

  1. Delivery stopped: check docker compose ps and the worker heartbeat on the admin status endpoint; restart sosopo-worker if unhealthy.
  2. Provider failures: open the post’s history, fix the credential or content issue, then use Retry — backoff and dead-lettering are automatic.
  3. Expiring tokens: the channel list flags them; X/LinkedIn/Threads refresh automatically, other providers need Rotate token or Reconnect.
  4. Suspected abuse: built-in per-IP rate limits apply; review the audit log and disable the account, then rotate any exposed credentials.
  5. Data requests: use workspace export for access requests and workspace deletion plus account disablement for erasure requests.

Health

Check /api/health and confirm both services are healthy with docker compose ps.

Backups

Create and verify backups regularly. Include database and uploaded media, then practice an isolated restore.

Public media

S3-compatible media needs a public HTTPS URL providers can fetch at publish time.

Reverse proxy

Use Cloudflare Tunnel, Traefik, Caddy, or Nginx Proxy Manager for HTTPS and keep app ports private.

docker compose run --rm sosopo python /app/scripts/preflight.py --production
docker compose run --rm sosopo python /app/scripts/backup.py
docker compose ps

HTTP API

Sosopo is API-first: everything the portal does goes through the same documented HTTP API. The complete description lives in openapi.yaml (OpenAPI 3.1), covering every /api/* endpoint.

Authentication uses a sosopo_session cookie, issued by /api/setup, /api/login, /api/signup, or the SSO callback. Every state-changing request must also carry an X-CSRF-Token header, read from GET /api/session as csrf_token.

Tenant scope is always resolved on the server from the session's active workspace. No endpoint accepts a workspace id from the client to choose a tenant.

A test asserts the spec and the code cannot drift apart in either direction: no route missing from the spec, and no spec path that no longer exists.

08 — Troubleshooting

Common fixes

ProblemWhat to check
Cannot save channel or AI API keySet a valid persistent SOSOPO_ENCRYPTION_KEY and restart both services first.
Model list does not refreshSave the provider key first and confirm its plan permits model discovery.
Cannot create a multi-platform postSelect a connected destination for every selected platform.
Scheduled post did not publishCheck worker health, open the post history, correct the provider error, and retry.
OAuth Connect is missingSet OAuth credentials and public HTTPS callback URL, then restart the stack.
Composer or Connect controls are missingYour role in the active workspace limits these actions: viewers cannot compose, and only workspace admins or the owner manage channel connections and members.
Invitation link says invalid or expiredInvitations expire after 7 days or after one use; ask a workspace admin to send a new one.
Generated media cannot be attachedA workspace admin must approve it in the Media tab first; rejected or other-workspace media is never publishable.
“Monthly limit reached” errorsThe workspace plan or AI cap was hit. The owner can upgrade the plan (hosted) or raise the cap; self-hosted workspaces are unlimited unless configured otherwise.
